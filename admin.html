Coupons

One coupon per order — codes never stack, and a coupon applies on top of whatever sale prices are already set. Pausing takes effect immediately, on the next checkout.
Send a personal code as a link and the customer never has to type it: steelo-design.com/?coupon=CODE

Leave unchecked for ללא כפל מבצעים — the coupon replaces any running sale. During a 10% sale, a 25% coupon then gives the customer 25% off the list price, not 32.5%. Tick it to have the coupon stack on top of the sale instead.

Funnel — unique people

Each bar is people, not events — one person adding three items is one add-to-cart.
The steps are not strictly nested: a shopper can add to cart from the homepage without ever opening a product page, so "of previous" can read above 100% on that step. "Of visitors" is the reliable number to watch.
The last two steps are recorded by the server, so they survive ad blockers; everything above them is undercounted by whatever share of visitors blocks scripts.

Meta events — Pixel vs Conversions API

Counted from what this server actually sent. Matched is the number of event IDs that appear on both channels — that is what Meta deduplicates on, and it is the number to compare against Events Manager.
Matched will never equal the totals, and shouldn't: a server event with no browser twin is an ad-blocked visitor finally being counted, which is the whole reason the Conversions API exists. Events Manager reports over a 7–28 day window, so it lags this table by days.

By traffic source

Source is first touch — where each person originally arrived from, even if they came back later by typing the address. Paid Meta traffic is identified by the fbclid Meta appends to every ad click, plus any utm_* on the link. These numbers will not match Ads Manager: Meta counts on its own attribution windows and loses iOS users to ATT, while this counts who actually reached the site.
